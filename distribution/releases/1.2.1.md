# Desktop 1.2.1 release verification

Verified 13 November 2026 on Windows, Windows PowerShell 5.1 and MATLAB
R2023b Update 3. This release adds structured update-failure diagnostics;
plugin versions and scientific algorithms are unchanged from 1.2.0.

- 18 PowerShell reporting checks, 16 updater checks, and an actual child-worker
  failure test passed. Native path-length/access errors, licensing-message
  recognition, consent, offline retry, arbitrary-field rejection and omission
  of private sentinel text were exercised. Worker failures preserve the active
  installation; the controller falls back if a worker dies before saving a report.
- MATLAB diagnostics/history/export and failed-candidate tests passed. A
  deliberately caught plugin-hook failure retained its underlying identifier
  and shipped-code stack instead of only the later generic inventory failure.
  Candidate reports start their own sender before activation.
- All 18 Node/PostgreSQL/OIDC checks passed. Schema 1 and older catalogs remain
  accepted; schema 2 rejects arbitrary log/message fields at every nesting level.
- The original 1.1.0 installer/updater installed the final 1.2.1 payload into
  a separate directory, passed all 53 inventoried registrations plus EEG-BIDS
  and both synthetic examples, activated it, and rolled back without altering
  the earlier installation.
- The installed Windows sender delivered a fabricated long-path failure
  without MATLAB running. Supabase acknowledged it, local history remained,
  and private GitHub delivery preserved its component, cause, OS code and
  environment. Live workflow `43519414884` also passed intake/privacy rejection,
  OIDC authentication, retry deduplication and grouped issue delivery.
  Synthetic support issues #12 and #13 were clearly marked and closed.

The Supabase function imports immutable source/catalog commit
`423e614570974b29d112a08087e29610fd1f9586`. The private collector uses
`ae30b8ffd437efb56208dc62689894d198610c61`. No access, credentials or database
permissions changed. Reporting remains opt-in. Raw logs, arbitrary error text,
recordings and personal paths are excluded. Older launchers must first obtain
the new package; unfamiliar errors can still require further investigation.
